# 写真共有アプリ 要件定義

## 1. アプリの概要

FlaskとPeeweeを使い、友人同士で旅行や日常の写真を見せ合える、インスタグラム風の小さな写真共有アプリを作る。

最初の完成版では、ユーザー登録・ログイン・写真投稿・投稿一覧を優先する。自分の投稿の削除とログアウトも実装する。インスタグラムのすべての機能を再現することは目指さない。

投稿は公開とし、URLを知っていればログインせずに閲覧できる。友人だけに限定した公開や招待制ではない。

## 2. 想定ユーザー

- 旅行や日常の写真を友人に見せたい人。
- 友人が投稿した写真を気軽に見たい人。
- 投稿する人は登録・ログインが必要。閲覧だけの人は登録不要。

## 3. 必須機能

### 3.1 ユーザー登録

- 公開ユーザー名（`username`）・メールアドレス・パスワードを入力して登録できる。
- 入力が空の場合や、メールアドレスの形式が不正な場合は登録せず、エラーを表示する。
- 同じメールアドレスでは重複登録できない。
- パスワードは平文で保存せず、ハッシュ化して保存する。
- `username` は入力必須・重複不可とし、空白だけの名前は登録できない。ログインには使わない。
- `username` は前後の空白を除去してから重複を判定し、大文字・小文字は区別する。`Alice` と `alice` は別の名前、` Alice ` と `Alice` は同じ名前とする。小文字への変換は行わない。
- 確認メールによるメール認証は今回の対象外とする。

### 3.2 ログイン

- 登録済みのメールアドレスとパスワードでログインできる。
- 認証に失敗した場合は、入力内容を確認するようエラーを表示する。
- ログイン状態を保持し、投稿した本人を識別できる。
- 未ログインで写真投稿画面にアクセスした場合は、ログイン画面へ案内する。

### 3.3 ログアウト

- ログイン中のユーザーがログアウトできる。
- ログアウト後も投稿一覧は閲覧できるが、投稿・削除には再ログインが必要となる。

### 3.4 投稿作成

- ログインしたユーザーだけが投稿できる。
- 1投稿につき写真1枚を必須とする。
- キャプションは任意とし、140文字まで入力できる。
- 写真がない場合や、キャプションが140文字を超える場合は保存せず、エラーを表示する。
- 投稿には、投稿者・写真の保存先・キャプション・投稿日時を記録する。
- 投稿が完了すると投稿一覧に反映される。

### 3.5 投稿一覧

- ログインの有無にかかわらず閲覧できる。
- 新しい投稿から順に表示する。
- 各投稿に投稿者の `username`・写真・キャプション（ある場合）・投稿日時を表示する。
- 投稿がない場合は、まだ投稿がないことを表示する。
- 投稿一覧・詳細では投稿者の `username` を公開し、メールアドレスは公開しない。

### 3.6 自分の投稿の削除

- ログインした本人の投稿だけ削除できる。
- 自分の投稿に削除ボタンを表示し、操作時に削除の確認を行う。
- 削除後は投稿一覧から消え、対応する写真ファイルも削除する。
- 他人の投稿は、URLなどを直接指定しても削除できない。
- キャプションの編集や写真の差し替えは実装しない。

### 3.7 必要な画面

| 画面 | 主な操作・表示 | ログイン |
| --- | --- | --- |
| 投稿一覧 | 写真を見る、自分の投稿を削除する | 閲覧は不要、削除は必要 |
| ユーザー登録 | `username`・メールアドレス・パスワードを登録する | 不要 |
| ログイン | メールアドレスとパスワードで認証する | 不要 |
| 写真投稿 | 写真1枚と任意のキャプションを投稿する | 必要 |

ログアウトは共通の画面メニューなどから操作できるようにし、専用画面は設けない。

## 4. 余裕があれば追加する機能

以下は必須機能の完成後に検討し、最初の完成版には含めない。

### 4.1 いいね

- ログインしたユーザーが投稿にいいねできる。
- 同じユーザーは1投稿に1回だけいいねでき、取り消しもできる。
- 投稿一覧にいいねの件数を表示する。

### 4.2 コメント

- ログインしたユーザーが投稿にコメントできる。
- 投稿についたコメントを閲覧できる。
- 自分のコメントだけ削除できる。

検索・フォローは今回の対象外とする。パスワード再設定、外部サービスによるログインも最初の完成版には含めない。

## 5. 非機能要件

### 5.1 技術と開発範囲

- Webアプリの処理にFlask、データの保存・取得にPeeweeを使用する。
- 初学者が扱いやすいよう、まずはローカル環境で動作する小規模な構成とする。
- SQLiteとプロジェクト直下のuploads/posts/への写真保存を採用する。公開先の選定は別途行う。
- 写真の加工や大規模なアクセスへの対応は、最初の実装には含めない。

### 5.2 使いやすさ

- 日本語で表示し、登録・ログイン・投稿・削除の操作が分かるようにする。
- スマートフォンとPCで、写真や入力フォームが画面からはみ出さないようにする。
- 写真の縦横比を保って表示する。
- 入力エラーは利用者が修正できる内容で表示する。

### 5.3 安全性とデータの保持

- パスワード、セッション用の秘密鍵などを公開しない。
- ログイン確認と投稿の所有者確認はサーバー側で行う。
- 登録・ログイン・投稿・削除などのフォームにCSRF対策を行う。
- キャプションをHTMLとして実行させず、文字列として表示する。
- アプリの再起動後も、ユーザー・投稿・写真が保持されるようにする。
- 公開する場合はHTTPSを利用し、デバッグモードを無効にする。

## 6. 実装時に注意すべきこと

### 6.1 写真ファイルを安全に扱う

- 許可する画像形式とファイル容量の上限を実装前に決める。PNG・JPG・JPEG・GIF、1枚5MB（5×1024×1024バイト）までとする。GIFは先頭フレームを静止画として保存する。
- 拡張子だけで判断せず、実際に読み込める画像かをサーバー側で確認する。
- 保存名はアプリ側で重複しない名前を生成する。利用者が指定したファイル名をそのまま保存先に使わない。
- 投稿の保存に失敗した場合、不要な写真ファイルだけが残らないようにする。
- 写真には位置情報などの付加情報が含まれることがある。公開する写真からは位置情報などのEXIF情報を除去する。

### 6.2 認証と公開情報を分ける

- メールアドレスは認証用として扱い、投稿一覧やエラーページに公開しない。
- メールアドレスの前後の空白や大文字・小文字の扱いを統一し、登録とログインで同じ処理を行う。
- 重複登録は画面側だけでなく、データベースの一意制約でも防ぐ。
- パスワード処理には既存のハッシュ化・検証機能を使い、独自の暗号処理を作らない。
- パスワードはちょうど4文字とし、登録画面に表示する。
- ボタンを隠すだけで権限制御を済ませない。削除時は毎回、投稿者とログイン中のユーザーを照合する。
- 削除はページを開くだけのGETリクエストでは実行しない。

### 6.3 小さく分けて実装する

| 順番 | 実装する範囲 | 完了の目安 |
| --- | --- | --- |
| 1 | Flaskの起動とPeeweeの接続 | アプリが起動し、データベースに接続できる |
| 2 | ユーザーの保存と登録画面 | 登録でき、`username` とメールアドレスの重複を防げる |
| 3 | ログインとログアウト | 認証でき、ログアウトで認証状態が解除される |
| 4 | 写真の保存と投稿画面 | ログイン中だけ写真1枚と任意のキャプションを投稿できる |
| 5 | 投稿一覧 | 未ログインでも新しい順に写真を閲覧できる |
| 6 | 投稿の削除 | 本人だけが削除でき、写真ファイルも削除される |
| 7 | 入力エラーと表示の確認 | 不正な入力を拒否し、スマートフォンでも操作できる |

安全性の対策は、対応する機能と一緒に実装する。最後にまとめて追加する前提にはしない。

### 6.4 最初の完成版で確認すること

- `Alice` の登録後も `alice` を登録できるが、`Alice` の再登録と前後に空白を付けた ` Alice ` の登録は拒否される。

- 未ログインで投稿一覧を閲覧でき、投稿・削除はできない。
- `username`・メールアドレス・パスワードで登録でき、メールアドレスとパスワードでログインし、ログアウトできる。
- 同じ `username` のユーザーは登録できず、投稿一覧・詳細に投稿者の `username` が表示される。
- 同じメールアドレスで重複登録できない。
- 写真なし、非対応ファイル、容量超過、141文字以上のキャプションを拒否できる。
- キャプションなし、または140文字のキャプションで投稿できる。
- 新しい投稿が一覧の先頭に表示される。
- 別のユーザーの投稿を削除できない。
- 自分の投稿を削除すると、一覧と保存先から対象の写真が消える。
- 公開画面にメールアドレスやパスワードが表示されない。

本書の「初期構成案」「初期案」は実装を進めるための提案であり、会話で確定した必須機能とは区別する。
