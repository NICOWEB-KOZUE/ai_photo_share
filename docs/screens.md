# 写真共有アプリ 画面設計

## 1. 設計の前提

[要件定義](requirements.md)と、その後の会話で確定した内容をもとにする。要件定義からの変更は、投稿詳細画面の追加と、削除ボタンを投稿一覧から投稿詳細へ移すことの2点とする。本設計ではこの最新の決定を採用する。

メールアドレスとパスワードで認証する。投稿一覧と投稿詳細は公開し、メールアドレスは表示しない。いいね・コメント・編集・検索・フォローの画面は今回作成しない。

## 2. 画面一覧

テンプレート名はFlaskの `templates/` からの相対パスとする。POSTはフォームの送信に使用する。処理の詳細は[ルーティング設計](routes.md)を参照する。


| 画面        | 目的               | ログイン          | URL                    | HTTPメソッド | テンプレート               |
| --------- | ---------------- | ------------- | ---------------------- | -------- | -------------------- |
| 投稿一覧（トップ） | みんなの写真を見る        | 不要            | `/`                    | GET      | `posts/index.html`   |
| ユーザー登録    | アカウントを作る         | 不要            | `/register`            | GET・POST | `auth/register.html` |
| ログイン      | 投稿できる状態にする       | 不要            | `/login`               | GET・POST | `auth/login.html`    |
| 投稿作成      | 写真1枚とキャプションを投稿する | 必要            | `/posts/new`           | GET・POST | `posts/new.html`     |
| 投稿詳細      | 1件の写真を大きく見る      | 閲覧は不要、削除は本人のみ | `/posts/<int:post_id>` | GET      | `posts/detail.html`  |


`post_id` は投稿の整数ID。例えば投稿12の詳細URLは `/posts/12` となる。

## 3. 共通レイアウト

全画面で `base.html` を継承し、上から共通メニュー、操作結果のメッセージ、各画面の内容を配置する。


| 状態     | 共通メニュー                |
| ------ | --------------------- |
| 未ログイン  | 投稿一覧、投稿作成、ログイン、ユーザー登録 |
| ログイン済み | 投稿一覧、投稿作成、ログアウト       |


- 未ログインで投稿作成を選ぶとログイン画面へ案内する。
- ログアウトはリンクではなくPOSTフォームのボタンにする。完了後は投稿一覧へ戻る。
- 成功時は「登録が完了しました」「投稿しました」などのメッセージを遷移先に表示する。
- スマートフォンでも操作できる幅にし、写真の縦横比を保つ。
- 公開ユーザー名 `username` を投稿一覧・詳細に表示し、メールアドレスを投稿者名の代わりに表示しない。



## 4. 各画面の内容と操作



### 4.1 投稿一覧

- 投稿者の `username`・写真・全文キャプション（ある場合）・投稿日時を1投稿ずつ縦に並べ、新しい順に表示する。
- 写真または「詳細を見る」から、その投稿の詳細へ進める。
- 投稿がない場合は「まだ投稿がありません」と表示する。
- 削除ボタンは表示しない。



### 4.2 ユーザー登録

- 公開ユーザー名（`username`）入力欄、メールアドレス入力欄、パスワード入力欄、「登録する」ボタンを配置する。
- `username` は必須・重複不可とし、前後の空白を除去して空になった場合はエラーにする。文字数上限はDB設計の初期案に合わせて50文字とする。
- `username` は前後の空白を除去してから重複を判定し、大文字・小文字は区別する。`Alice` と `alice` は別の名前、` Alice ` と `Alice` は同じ名前とする。小文字への変換は行わない。
- 登録済みの人向けにログイン画面へのリンクを表示する。
- 必須入力・文字数・メール形式・`username` とメールアドレスの重複などのエラーは同じ画面に表示する。
- `username` が重複した場合は「このユーザー名は既に使用されています」と表示する。
- エラー時は `username` とメールアドレスを保持するが、パスワードは再入力とする。
- 登録成功後はログイン画面へ進む。自動ログインはしない。



### 4.3 ログイン

- メールアドレス入力欄、パスワード入力欄、「ログイン」ボタンを配置する。
- 未登録の人向けにユーザー登録画面へのリンクを表示する。
- 認証失敗時は同じ画面で「メールアドレスまたはパスワードを確認してください」と表示する。
- エラー時はメールアドレスを保持するが、パスワードは再入力とする。
- 成功後は常に投稿一覧へ進む。投稿作成から案内された場合も同じとする。
- ログイン済みで登録・ログイン画面を開いた場合は、投稿一覧へ戻す。



### 4.4 投稿作成

- 写真の選択欄、キャプションの入力欄、「投稿する」ボタン、投稿一覧へ戻るリンクを配置する。
- 写真は1枚必須、キャプションは任意・140文字までと案内する。
- 許可する画像形式と容量上限も入力欄の近くに表示する。PNG・JPG・JPEG・GIF、1枚5MBまで。GIFは先頭フレームを静止画として保存する。
- 写真なし、不正な画像、容量超過、文字数超過の場合は投稿せず、エラーを表示する。
- 通常の入力エラーでは同じ画面にキャプションを保持し、写真は再選択を案内する。
- 成功後は投稿一覧へ戻る。キャンセルに相当する「投稿一覧へ戻る」では保存しない。



### 4.5 投稿詳細

- 写真を一覧より大きく表示し、投稿者の `username`・全文キャプション（ある場合）・投稿日時を表示する。
- 「投稿一覧へ戻る」リンクを配置する。
- ログイン中の投稿者本人だけに「削除する」ボタンを表示する。
- 削除時はブラウザーの確認ダイアログで「この投稿を削除しますか？」と確認する。
- キャンセル時は送信せず詳細に留まる。確認した場合は削除用URLへPOSTし、成功後は一覧へ戻る。
- 専用の削除確認画面は設けない。削除権限はサーバー側でも確認する。



## 5. 画面遷移


| 起点・操作                   | 遷移先・結果        |
| ----------------------- | ------------- |
| 投稿一覧で写真・詳細リンクを選ぶ        | 投稿詳細          |
| 投稿詳細で一覧へ戻る              | 投稿一覧          |
| 共通メニューで投稿作成を選ぶ（ログイン済み）  | 投稿作成          |
| 共通メニューで投稿作成を選ぶ（未ログイン）   | ログイン          |
| ユーザー登録に成功する             | ログイン          |
| ログインに成功する               | 常に投稿一覧        |
| 写真投稿に成功する               | 投稿一覧          |
| 投稿作成で一覧へ戻る              | 投稿一覧（保存しない）   |
| 投稿詳細で削除を確認し、削除に成功する     | 投稿一覧          |
| ログアウトする                 | 投稿一覧          |
| 登録・ログイン・投稿で通常の入力エラーが起きる | 元の入力画面にエラーを表示 |




## 6. エラー表示

主画面は5つとし、例外時の表示には共通の `errors/error.html` を使う。

- 存在しない・削除済みの投稿は404「投稿が見つかりません」とし、一覧へのリンクを表示する。
- 他人の投稿への削除リクエストは403「この操作はできません」とする。
- 不正なCSRFトークンは400とし、画面を開き直すよう案内する。
- アップロード全体がリクエスト容量の制限を超えた場合は413とし、投稿作成へのリンクを表示する。この場合は入力内容を保持しない。
- 詳細な内部エラーや個人情報は表示しない。
