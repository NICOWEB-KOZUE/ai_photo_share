# AI向けコンテキスト

## 目的と読む順序

友人同士で旅行や日常の写真を共有する、初学者向けの小さなWebアプリ。まずローカル環境で必須機能を完成させる。

本書 → [実装ルール](coding_rules.md) → [タスク](tasks.md) → 担当機能に関係する設計書の順に読む。

| [requirements.md](requirements.md) | 目的、必須機能、対象外 |
| [screens.md](screens.md) | 表示内容、画面遷移 |
| [routes.md](routes.md) | URL、HTTPメソッド、テンプレート名 |

最新のユーザー指示を優先する。本書の「確定事項」は会話で決定済みであり、元資料に残る古い記述より優先する。それ以外の矛盾は推測で仕様変更せず確認する。詳細表は元資料を参照し、重複して管理しない。

## 確定事項

- FlaskとPeeweeは変更しない。DBはSQLite、画像はローカル保存。
- 画面は登録・ログイン・投稿一覧・投稿作成・投稿詳細の5つ。一覧・詳細はログイン不要。
- 登録項目は `username`・メール・パスワード。ログインはメールとパスワード。
- `username` は必須・重複不可。前後の空白を除去し、大文字・小文字を区別する。`Alice` と `alice` は別、` Alice ` と `Alice` は同じ。公開画面には名前を表示し、メールを表示しない。
- メールは前後の空白除去・小文字化を登録とログインで統一し、重複を禁止する。
- パスワードはちょうど4文字。文字種の組み合わせを強制しない。保存はハッシュのみ。
- サーバー側セッションでログイン状態を管理する。最後の利用から24時間で期限切れ、ログアウトで解除する。
- 投稿は写真1枚必須。JPEG・PNG・GIF、1枚5MBまで。キャプションは任意・140文字まで、未入力は空文字。
- 画像の保存先は **プロジェクト直下の `uploads/posts/`**。`static/` はCSS・JSなど開発者が用意するファイル用。
- 一覧は投稿日時の降順、同時刻ならIDの降順。日時はUTC保存、日本時間表示。
- 削除は本人の投稿詳細からのみ行い、確認後にPOSTする。投稿と対応する画像を削除する。
- 登録成功→ログイン、ログイン成功→常に一覧、投稿・削除・ログアウト成功→一覧。
- 最初のDBテーブルは `users` と `posts`。`likes` は将来案のみ。
- いいね・コメント・編集・検索・フォロー・メール認証・パスワード再設定・退会は今回実装しない。

元の要件定義には「4画面・一覧から削除」「SQLite・画像制限は初期案」「パスワード条件は未決定」が残る。上記で確定済みなので再質問しない。着手時にT01で資料の整合を取る。

## 採用パッケージ

バージョンはプロジェクト直下の [requirements.txt](../requirements.txt) を参照し、独断で更新しない。

| パッケージ | 用途 |
| --- | --- |
| Flask / peewee | Web処理 / SQLite操作 |
| Flask-Login | ログイン・ログアウト、current_user、ユーザーIDからの復元 |
| Flask-Session / cachelib | サーバー側セッション。CacheLibのファイル保存を使用 |
| Flask-WTF / WTForms / email-validator | フォーム、CSRF、入力・メール形式の検証 |
| Pillow | 画像の実体検証、向き補正、EXIFを除いた再保存 |
| python-dotenv | 開発用 `.env` の読み込み |
| Werkzeug | パスワードのハッシュ化・照合（Flaskの依存） |
| pytest | 重要部分の自動テスト。テスト着手時に開発用依存として追加 |

## 構成方針

必要になったものだけ作る。下記はプロジェクト直下からの相対パス。

| パス | 役割 |
| --- | --- |
| `app.py` | アプリ生成関数 `create_app`、拡張初期化、ルート登録。最初はBlueprint不要 |
| `config.py` | 環境変数と保存先の設定。テスト時は設定を差し替え可能にする |
| `models.py` | Peewee接続、User・Postモデル。app.pyを読み込まない |
| `forms.py` | フォームと検証 |
| `image_utils.py` | 画像の検証・保存・削除 |
| `templates/` | 設計済みのHTMLテンプレート |
| `static/` | CSS・JS |
| `uploads/posts/` | ユーザー投稿画像。プロジェクト直下に置く |
| `instance/app.sqlite3` | 業務データ |
| `instance/sessions/` | 非公開のセッションデータ |
| `.env` / `.env.example` | ローカルの秘密情報 / 秘密を含まない設定見本 |
| `tests/` / `requirements-dev.txt` | 自動テスト / 開発用依存 |

画像配信の補完設計は `GET /uploads/posts/<filename>`、エンドポイント名 `uploaded_file`、ログイン不要・テンプレートなしとする。これはHTML画面とは別のルートで、routes.mdにも記載済み。

## 未確定事項

- DB設計にある上限案（username 50文字、メール254文字、生成ファイル名255文字）はユーザーが確定した値とは区別し、T01で確認する。
- 公開先は未定。初期実装はローカルに限定し、公開用インフラは追加しない。
- 容量表記の実装上の既定値は5MB＝5×1024×1024バイトとする。フォーム全体の制限とは分ける。

依頼されたタスクと必要な確認まで進め、無関係な機能を追加しない。完了後は変更内容・確認結果・残件を短く報告する。

## 認証の実装状況

登録・ログイン・POSTログアウトを実装済み。Flask-LoginとFlask-Sessionを併用する。Userの既存カラムを使用し、DB変更は不要。ユーザー名は現行モデルに合わせて最大50文字、メールは254文字で検証する。

起動前にSECRET_KEYを環境変数または.envへ設定する（設定項目はプロジェクト直下の.env.example）。直接実行はポート8000。Flask CLIで起動する場合は初回にinit-dbを実行する。認証の自動テストは `.venv/bin/python -m pytest -q -p no:cacheprovider` で実行する。

## 写真投稿の実装状況

ログイン必須のGET・POST /posts/newと、公開GET /uploads/posts/<filename>を実装。画像はプロジェクト直下のuploads/posts/に保存。PNG・JPG・JPEG・GIF、1枚5MiBまで。GIFは先頭フレームをPNGとして保存する。トップには画像・username・日本時間の日時・キャプションを新しい順に表示。画像単体の5MiBとフォーム全体の6MiBを別々に検証する。
