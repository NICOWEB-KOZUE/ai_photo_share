# 写真共有アプリ ルーティング設計

## 1. 基本方針

[画面設計](screens.md)に対応するFlaskのルートを定義する。[要件定義](requirements.md)の作成後に確定した「投稿詳細画面を追加する」「削除は投稿詳細だけから行う」を反映する。

- GETは表示、POSTはフォームの送信・状態の変更に使う。
- 登録・ログイン・投稿作成は、同じURLと同じビュー関数でGETとPOSTを扱う。
- 削除とログアウトはPOST専用にし、専用画面は設けない。
- POST成功後は302リダイレクトで次の画面のGETへ移る。再読み込みによる二重送信を防ぐ。
- 以下のエンドポイント名をビュー関数名として使い、リンクとフォーム送信先はFlaskの `url_for` で生成する。最初はBlueprintによる分割を必須としない。
- テンプレート名は `templates/` からの相対パス。すべての画面テンプレートは `base.html` を継承する。

## 2. ルート一覧

| URL | HTTPメソッド | エンドポイント名 | 目的・処理 | ログイン | テンプレート／成功後の遷移 |
| --- | --- | --- | --- | --- | --- |
| `/uploads/posts/<filename>` | GET | `uploaded_file` | 投稿に紐づく画像を配信 | 不要 | テンプレートなし。存在しなければ404 |
| `/` | GET | `post_index` | 投稿を新しい順に取得・表示 | 不要 | `posts/index.html` |
| `/register` | GET | `register` | 登録フォームを表示 | 不要 | `auth/register.html` |
| `/register` | POST | `register` | 入力を検証し、ユーザーを登録 | 不要 | `/login` へリダイレクト |
| `/login` | GET | `login` | ログインフォームを表示 | 不要 | `auth/login.html` |
| `/login` | POST | `login` | 認証し、ログイン状態を保存 | 不要 | 常に `/` へリダイレクト |
| `/logout` | POST | `logout` | ログイン状態を解除 | 必要 | `/` へリダイレクト |
| `/posts/new` | GET | `post_create` | 投稿フォームを表示 | 必要 | `posts/new.html` |
| `/posts/new` | POST | `post_create` | 写真と入力を検証し、投稿を保存 | 必要 | `/` へリダイレクト |
| `/posts/<int:post_id>` | GET | `post_detail` | 指定した投稿を取得・表示 | 不要 | `posts/detail.html` |
| `/posts/<int:post_id>/delete` | POST | `post_delete` | 本人の投稿と写真ファイルを削除 | 必要・投稿者本人のみ | `/` へリダイレクト |

`<int:post_id>` はFlaskの整数パラメーター。例：詳細 `/posts/12`、削除 `/posts/12/delete`。削除URLをGETで開いても削除せず、405（許可されないメソッド）とする。ログアウトのGETも同様。

## 3. フォームと処理結果

すべてのPOSTフォームにCSRFトークンを含める。以下の入力項目名はフォームとビュー関数で統一する。

| 処理 | 入力項目名 | 成功時 | 入力・認証エラー時 |
| --- | --- | --- | --- |
| 登録 | `username`、`email`、`password` | ユーザーを保存し、登録完了を表示してログインへ | `auth/register.html` にエラーと入力した `username`・メールアドレスを表示 |
| ログイン | `email`、`password` | ログイン状態を保存し、一覧へ | `auth/login.html` にエラーとメールアドレスを表示 |
| 投稿作成 | `photo`、`caption` | ログイン中のユーザーを投稿者として保存し、一覧へ | `posts/new.html` にエラーとキャプションを表示。写真は再選択 |
| 削除 | URLの `post_id` | 投稿と写真を削除し、一覧へ | 権限不足は403、対象なしは404 |
| ログアウト | 追加入力なし | ログイン状態を解除し、一覧へ | 未ログイン時はログインへ |

- 通常の入力・認証エラーはHTTP 200で同じフォームを再表示し、保存やリダイレクトは行わない。
- `username` が重複した場合は「このユーザー名は既に使用されています」と登録画面に表示する。
- `username` は前後の空白を除去してから重複を判定し、大文字・小文字は区別する。`Alice` と `alice` は別の名前、` Alice ` と `Alice` は同じ名前とする。小文字への変換は行わない。
- パスワードはエラー時にフォームへ埋め戻さない。
- 写真の送信フォームは `multipart/form-data` を使う。画像の形式・容量・内容をサーバー側で検証する。
- 投稿者IDをフォーム入力として信用せず、ログイン状態から決定する。
- 登録では `username` を必須・重複不可とし、空白だけの名前を拒否する。前後の空白を除去し、文字数上限はDB設計の初期案に合わせて50文字とする。`username` とメールアドレスの重複をDBのユニーク制約でも防ぎ、パスワードをハッシュ化する。登録成功時点ではログイン状態にしない。
- CSRFエラーは400、リクエスト容量制限超過は413として `errors/error.html` を表示する。容量制限超過時は入力内容を保持しない。

## 4. ログインと権限の扱い

| 状況 | 動作 |
| --- | --- |
| 未ログインで一覧・詳細へアクセス | そのまま表示 |
| 未ログインで投稿作成・削除・ログアウトへアクセス | `/login` へ302リダイレクトし、操作は実行しない |
| 投稿作成から案内されてログインに成功 | `/` へ移動。投稿作成へ自動では戻さない |
| ログイン済みで `/login`・`/register` にアクセス | `/` へ302リダイレクト |
| ログイン済みで他人の投稿を削除しようとする | 403。データもファイルも削除しない |
| 詳細表示や、ログイン済みの削除で投稿が存在しない | 404 |

CSRF検証があるPOSTでは、不正なトークンを400として拒否する。上表のPOSTの遷移はCSRF検証を通過した場合の動作とする。未ログイン中に送信した投稿・削除は、ログイン後に自動再実行しない。

削除時はログイン確認、投稿の取得、投稿者の照合をサーバー側で行う。ブラウザーの確認ダイアログやボタンの表示条件だけで権限を制御しない。

## 5. テンプレートへ渡す主な情報

| テンプレート | 表示に必要な情報 |
| --- | --- |
| `base.html` | ログイン状態、操作結果のメッセージ |
| `posts/index.html` | 新しい順の投稿一覧（ID・写真URL・キャプション・投稿日時・投稿者の `username`） |
| `auth/register.html` | 入力した `username`・メールアドレス、入力エラー |
| `auth/login.html` | 入力したメールアドレス、認証・入力エラー |
| `posts/new.html` | 入力したキャプション、入力エラー、画像形式・容量の案内 |
| `posts/detail.html` | 対象の投稿と投稿者の `username`、ログイン中のユーザーが削除できるかどうか |
| `errors/error.html` | HTTPステータスに応じた案内、安全な戻り先リンク |

写真URLは保存済み画像を表示するためのURLであり、投稿詳細URLとは別。画像はプロジェクト直下のuploads/posts/に保存し、GET /uploads/posts/<filename>（uploaded_file、ログイン不要）からsend_from_directoryで配信する。DBに対応投稿がない画像は404とする。メールアドレスやパスワードハッシュは公開画面へ出力しない。

## 6. 画面遷移の確認項目

- `Alice` の登録後も `alice` を登録できるが、`Alice` の再登録と前後に空白を付けた ` Alice ` の登録は拒否される。

- 未ログインでも一覧から詳細へ進み、一覧へ戻れる。
- 登録では `username` が必須・重複不可となり、エラー時は `username` とメールアドレスが保持される。
- 一覧・詳細には投稿者の `username` が表示され、メールアドレスは公開されない。
- 登録成功後はログイン、ログイン成功後は必ず一覧へ進む。
- 未ログインで投稿作成を開くとログインへ進み、ログイン後は一覧から投稿作成を開き直せる。
- 投稿成功後に一覧へ戻り、再読み込みで同じ投稿が再送信されない。
- 削除ボタンは本人の投稿詳細だけに表示され、キャンセル時は詳細に留まる。
- 削除成功後は一覧へ戻り、削除済みの詳細URLは404になる。
- 他人の投稿の削除URLへPOSTしても403となり、GETでは削除できない。
- ログアウト後は一覧に戻り、投稿作成には再ログインが必要になる。

本書は画面に対応するルートとフォーム操作の設計とし、アプリのコードは含めない。
